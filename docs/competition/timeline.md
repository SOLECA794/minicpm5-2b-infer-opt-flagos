## 3. 无卡期间能做完的事（不要空等）

这些**不需要 GPU**，现在就能全部完成：

1. ✅ 框架源码全量静态调研（subagent 进行中）
2. ✅ 平台 API 抓取与规则固化（已完成）
3. ⬜ 把 `benchmark_throughput_serve.py` / `run_eval.sh` 本地化 + 加结果解析
4. ⬜ 写一个 **baseline 复现校验脚本**：读 `summary_*.csv`，比对官方 baseline，
   偏差 > 1% 就报警
5. ⬜ 写一个 **性能提升计算器**：输入两卡两场景的 before/after，直接算总分
6. ⬜ 用 CPU / 小模型（如 MiniCPM5-1B 或直接 MiniCPM5-2B 的 CPU bf16）
   跑通 vllm-plugin-FL 的 import / 单测，确认代码结构理解无误
7. ⬜ 把优化点拆成**可独立开关的 patch**，每个 patch 自带 hypothesis + 预期指标
8. ⬜ 技术报告骨架（章节结构 + 图表占位）

## 4. 自备算力预案

如果 11-01 仍未拿到官方卡：

* 沐曦曦云 C500 有公开云平台（模力方舟），可按小时付费
* 天数 BI-V150 可通过天数智芯生态渠道申请试用
* 兜底：先在**任一 CUDA GPU** 上验证「优化是否成立」（很多优化是框架层的，
  与后端无关），再迁移；但最终提交必须有两卡数据

> 注意：官方算力申请**不影响参赛资格**。赛季一 FAQ 明确写了
> 「即使未申请到组委会的算力资源，团队仍然可以使用自有算力或第三方平台完成作品」。
> 所以算力申请失败 ≠ 出局，只是成本上升。

## 5. 风险登记

| 风险 | 概率 | 影响 | 缓解 |
|---|---|---|---|
| 算力申请被拒 / 排队太久 | 中 | 高 | 10-21 前投递抢先后；同步准备自备算力 |
| 天数卡 prefill 瓶颈在驱动/编译器层，非我们可改 | 中 | 高 | 先做框架层优化（一定有效），内核层作为加分项 |
| 沐曦侧不带 cudagraph 配置，覆盖手段受限 | 高 | 中 | 在插件 config 层注入等价配置，或证明 cudagraph 非必要 |
| 精度掉到 0.95 以下 | 低 | 致命 | 每轮优化后立刻跑 evalscope，不攒到最后 |
| TTFT 变差超过 1% | 中 | 致命 | 每个吞吐优化都先算 TTFT 预算 |
| 报告与代码不一致被判 0 分 | 低 | 致命 | 报告里每个策略标 commit / patch 名 |
