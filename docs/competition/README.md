## 1. 一句话结论

在**不改动 serve 参数、不换模型、不降低精度**的前提下，把 MiniCPM5-2B 在
**天数智芯 BI-V150** 和 **沐曦曦云 C500** 上的 `total tokens/s` 顶上去。
分数 = 两款卡各自的性能提升比例（70%）+ 技术报告创新性专家评分（30%）。

## 4. 算力申请规则（决定我们能不能开跑）

* **材料命名**：`算力申请-[队名].pdf`（注意是 **PDF**，不是 zip；赛季一才是 zip）
* **材料内容（至少）**：
  1. **初步技术方案** —— 权重 60%
     * 任务理解是否准确（20%）
     * 技术路线是否合理且**具有可复现性**（20%）
     * 实验计划与时间安排是否清晰（10%）
     * 是否具有创新性或合理的技术改进点（10%）
  2. **团队介绍** —— 权重 40%
     * 相关研究或工程背景（15%）
     * 过往竞赛或项目经验（15%）
     * 团队分工合理性与成员稳定性（10%）
* **审核**：提交后 5 个工作日内出结果
* **算力使用方式**：
  * 天数 → 审批通过后在 <https://flagos.io/OnlineLab> 预约
  * 沐曦 → 领算力券后在 <https://ai.gitee.com/compute> 兑换（额度有限，闲置请关机；建议每 36h 开关机一次防数据丢失）
* **不浪费原则**：申请了就必须用，写清具体要多少卡时、用来干什么

> 详细规则见 [`rules-s2-track2.md`](rules-s2-track2.md)。

## 5. 评分公式（原文）

```
总分 = 性能分（天数卡）+ 性能分（沐曦卡）+ 创新分

性能分 = 100 × 性能提升比例 × 70%
  例：baseline 200 → 210，提升 5%，性能分 = 100 × 5% × 70% = 3.5

创新分 = 专家评分 × 30%
  评判维度：系统级调度、算子编译优化创新等原创优化思路

单一场景超过 1% 才赋分；最终取 4k / 16k 两个场景的平均
性能指标偏差 1% 以内视为正常波动
```

**战略含义**：创新分是 30% 的独立板块，而性能分是「提升比例 × 0.7」——
每 1% 性能只换 0.7 分。所以：

1. **两款卡都要出成绩**（加法关系，不是取最好）
2. **技术报告必须写得像论文**，不能像 commit log——30% 的分在这里
3. 性能上先打**最容易的大头**（见 [`../research/`](../research/)），
   不要一上来抠 0.3% 的 kernel micro-opt

## 6. 绝对红线（踩了直接 0 分）

| 禁止项 | 说明 |
|---|---|
| 换模型 | 只能用 MiniCPM5-2B |
| 改 serve 参数 | 必须与 baseline 完全一致 |
| 改超参开量化 / 投机采样 | 明确禁止 |
| 调优 benchmark 脚本 | 明确禁止 |
| 无算子优化就切算子 / 删掉框架算子选择逻辑 | 明确禁止 |
| 直接 merge 上游最新分支代码 | 明确禁止（必须自己写） |
| 精度降幅超范围 | 精度 < 0.95 即无效 |
| TTFT 明显变差 | > baseline + 1% 即无效 |
| 方案无法复现 | 成绩无效 |
| 未按时提交 PR | 取消获奖资格 |

> 「提交的技术报告中的策略必须体现在提交代码中，并在最终版本使用上对应的优化策略。」
> —— 报告和代码必须一一对应，不能报告吹 A 代码跑 B。
